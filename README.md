# JCOE 공정 시뮬레이터

세아제강 포항공장 JCOE 강관 생산 라인의 **공정 흐름 시뮬레이터**입니다.
POSTECH 산업경영공학과 IDEA Lab × 세아제강 「철강 제조 공정의 실시간 대응을 위한 지능형 시스템 개발」 과제 산출물.

공정 다이어그램(PPT)의 실제 흐름을 그대로 재현하고, 표준시간 산출식 엑셀(SMART기술팀, 2025-12-18)의
19개 공정 계산식을 브라우저에서 재계산합니다. 확관기 배분 규칙과 최적화 엔진을 포함합니다.

두 개의 산출물이 있으며 **둘 다 의존성 없는 단일 HTML 파일**입니다. 브라우저로 열기만 하면 됩니다.

| 파일 | 크기 | 내용 |
|---|---|---|
| [`dist/JCOE_Simulator.html`](dist/JCOE_Simulator.html) | ~764 KB | 2D — 공정 흐름 / 표준시간 계산기 / In·Out 시간표 / 확관 배분·최적화 / 오더 스케줄 / 병목 분석 |
| [`dist/JCOE_3D.html`](dist/JCOE_3D.html) | ~1.4 MB | 3D — 공정 흐름도 입체화 + 자재 적치·이동 애니메이션 (three.js 내장, 오프라인 동작) |

### 3D 시뮬레이터 (`dist/JCOE_3D.html`)

2D 다이어그램 좌표를 1:1로 3D 공간에 투영했습니다. 위에서 보면 2D 도면과 같은 배치입니다.

- **설비 형상** — 밀링 베드, 프레스 갠트리, 용접 토치·와이어릴, 확관기 드로바, 수압 압력용기, X-ray 포털, 포장 밴딩 스테이션을 공정별로 구분
- **자재 흐름** — 후판(판재) → U/O 성형 반제품 → 강관으로 형상이 바뀌며, 각 설비 앞에 대기 자재가 실제로 쌓입니다. 확관 대기분은 10번 문 Buffer 랙에 적치
- **야드** — 원자재(후판) 야드는 줄고 완제품 야드는 늘어납니다. 28.5일 완주 시 후판 0매 / 완제품 1,401본
- **호기 분리** — 확관 #1·#2호기, 내면·외면 SAW 4라인, F-X ray 2대가 물리적으로 분리된 설비로 표시
- **조작** — 좌 드래그 회전 / 우 드래그(또는 Shift) 이동 / 휠 확대 / 설비 클릭 시 가동률·전환시간·산출식
- **재생** — 타임라인 슬라이더로 임의 시점 점프·되감기, 반복 재생, 변동성 토글, 🎲 새 시드 재실행

### 계획서 불러오기

기본 데이터는 2026년 3월 포항공장 조관계획서 기준 58오더 / 1,446본이지만, **다른 계획서 엑셀을 넣어 바로 돌릴 수 있습니다.**

2D는 「계획서 · 설정」 탭, 3D는 상단 **계획서 불러오기** 버튼에서 파일을 끌어다 놓으면 됩니다.
`.xlsx` / `.xlsm` / `.xls` / `.csv` 를 읽습니다.

- **시트·헤더 행 자동 탐지** — 표지 시트나 제목 몇 줄이 위에 있어도 실제 헤더 행을 찾습니다. `JCOE` 가 들어간 시트를 우선 선택합니다
- **열 자동 인식** — `오더번호/제번/작번`, `외경/O.D`, `두께/육후/WT`, `길이/L`, `수량/본수/PCS`, `계획일/투입일자`, `납기/요청일` 등의 표기를 인식합니다. 못 찾으면 숫자 분포로 추정하고, 그래도 틀리면 화면에서 직접 지정할 수 있습니다
- **단위 자동 추정** — 외경 중앙값이 120 미만이면 inch, 길이 중앙값이 60 미만이면 m 로 판단해 mm 로 환산합니다. 수동 변경 가능
- **검증** — 필수값 누락·수량 0·범위 이탈 행은 건너뛰고 사유를 행 번호와 함께 표시합니다
- **필수 열은 외경·두께·길이·수량** 네 가지. 오더번호가 없으면 행 번호로, 계획 투입일이 없으면 시작일부터 순차 배치합니다
- 적용하면 공정 흐름·간트·병목·In/Out·최적화가 모두 새 데이터로 다시 계산됩니다. `orders.json` 내보내기와 기본 데이터 되돌리기도 지원합니다

형식 변형 테스트용 샘플은 `testdata/` 에 있고, `python3 tools/make_test_plans.py` 로 다시 만들 수 있습니다.

### 확률 변동 (Stochastic) 실행

기본은 **결정론**입니다 — 몇 번을 돌려도 결과가 같습니다. 「반복 실행」 탭에서 변동성을 켜면
**실행할 때마다 다른 결과**가 나옵니다.

| 요소 | 모델 |
|---|---|
| 작업시간 변동 | 표준시간 × 로그정규(평균 1, CV 기본 0.10) |
| 전환시간 변동 | 전환시간 × 로그정규(CV 기본 0.20) |
| 불량 발생 | F-X ray 에서 본당 확률 `pDefect`(기본 2%) → **Repair** → 65% 는 **보수 용접 → 재검사**, 35% 는 **Expander 문제 → 재확관** |
| 설비 고장 | MTBF/MTTR (기본 무고장). 작업 중 확률적으로 고장나 지수분포 수리시간만큼 정지 |

불량 라우팅을 켜야 다이어그램에 그려만 놓고 아무도 지나가지 않던 **Repair · 보수 용접 · 재확관 루프가 실제로 동작**합니다.
난수는 시드 기반이라 같은 시드면 같은 결과가 나오고, 🎲 버튼이나 「새 시드로 실행」으로 시드를 바꿉니다.

**반복 실행(몬테카를로)** 은 시드를 바꿔가며 N회 돌려 분포를 냅니다 (100회 ≈ 6초).

| 지표 | P10 | P50 | P90 | 평균 ± 편차 |
|---|---:|---:|---:|---|
| 완료 소요(일) | 28.5 | 29.3 | 30.1 | 29.4 ± 0.5 |
| 확관 전환(h) | 80.1 | 83.8 | 89.3 | 85.0 ± 3.9 |
| 재작업(본) | 22 | 29 | 41 | 30 ± 8 |

> *조건: 2교대 7.5H, CV 0.10/0.20, 불량률 2%, MTBF 200h, 최단 가용 규칙, 20회*

배분 규칙 5종을 각각 반복하면 **규칙 간 차이가 변동성에 묻히는지** 판별할 수 있습니다.
현재 데이터에서는 완료일 P50 이 29.2~29.6일로 P10~P90 폭(약 1.5일) 안에 전부 들어가 **유의한 차이가 아니고**,
확관 전환시간은 50.3h(최적화) ~ 91.6h(균등 배분)로 편차(±2~4h)를 크게 넘어 **명확히 유의합니다.**

## 2. 확관기 공정 제약 (모델의 핵심)

원자료의 제약을 그대로 풀면 공정 다이어그램 주석과 정확히 일치합니다.

| 설비 | 공정 제약 (원문) |
|---|---|
| 확관 1호기 | 14m 이상 작업 불가 · **2호기와 동시 작업 시 동일 외경 제품만 가능** |
| 확관 2호기 | 12.8m 이상 작업 불가 · 외경 48 inch 이상 & 22 inch 이하 우선 투입 |
| 확관 3호기 | 12.8m 이상 작업 불가 · 열처리 공정 제품 & 배척 제품 우선 투입 |

이를 길이로 정리하면

- **L < 12.8m** — #1·#2호기 중 선택 가능 → **배분 규칙이 실제로 작동하는 구간**
- **12.8m ≤ L < 14m** — #2·#3호기 불가 → **#1호기 전용** (다이어그램 주석의 *"12.8M~14M 제품 Only #1 Expander 가동"*)
- **L ≥ 14m** — 어느 호기도 단독 불가 → **#1·#2호기 동시 가동**, 소요시간 = `max(#1, #2)`
  (다이어그램 주석의 *"14M 초과 제품 #1,#2 Expander 가동"*. 1호기 칸의 "2호기와 동시 작업 시 동일 외경 제품만 가능"이 이 동시 작업을 규정)

현재 오더셋(58오더 1,446본) 기준 분포:

| 구분 | 오더 | 본수 |
|---|---:|---:|
| 두 호기 다 가능 (L < 12.8m) — 배분 규칙 대상 | 23 | 111 |
| #1호기 전용 (12.8~14m, 대부분 12.802m) | 26 | 960 |
| #1·#2 동시 가동 (L > 14m) | 2 | 280 |

물량의 66%가 12.802m라 구조적으로 #1호기에 몰립니다. 호기 부하 편차는 배분 규칙이 아니라
**제품 길이 구성**에서 나옵니다.

> **확인 필요** — 확관 3호기는 제약표에는 3대로 기재되어 있으나 공정 다이어그램에는 "2개 라인 보유"로
> 되어 있습니다. 시뮬레이터에서는 옵션 토글로만 제공하며 기본값은 OFF 입니다.

## 3. 최적화 엔진

PPT「최적화 모델 구성」의 수식을 그대로 구현했습니다 — 병렬설비 + 순서의존 전환시간 스케줄링.

```
min  ①
s.t. ② Σ(m∈ℳ) z(j,m) = 1                      ∀j ∈ 𝒥        모든 작업은 정확히 한 설비에
     ③ z(j,m) = 0                              ∀(j,m) ∉ ℰ    적격집합 밖은 배정 불가
     ④ S(j) ≥ C(i) + s(ij) − M(1 − x(ij))      ∀m ∈ ℳ, ∀i,j ∈ 𝒥(m)
```

- 작업 `j` = 오더, `p(j,m)` = 수량 × 호기별 사이클타임, `s(i,j)` = 규격 변경 전환시간
- 목적함수 ①은 원자료에 비어 있어 **`w₁·Makespan + w₂·Σ전환시간 + w₃·호기부하편차`** 로 정의했습니다 (가중치는 화면에서 조정)
- 해 표현 = 전역 작업순서 `order[]` + SINGLE 작업의 호기 배정 `assign{}`
- 평가 = 전진 시뮬레이션. **BOTH 작업(L ≥ 14m)은 #1·#2호기를 동시 점유**
- 규격 그룹핑 Greedy 초기해 → Simulated Annealing (swap / shift / 재배정), 24,000회 ≈ 0.6초
- 난수는 LCG 고정 시드(20260804) — **같은 입력이면 같은 해**가 나옵니다

### 배분 규칙별 결과 (2교대 7.5H/Shift, 동일외경 동시작업 제약 ON, 3호기 제외)

| 배분 규칙 | Makespan | 확관 전환 | 총 전환 | #1 / #2 (본) | 부하 편차 |
|---|---:|---:|---:|---:|---:|
| 최단 가용 (Earliest Available) | 28.5일 | 87.0h | 265h | 1,281 / 350 | 150.7h |
| 균등 배분 (Round-robin) | 28.5일 | 92.5h | 270h | 1,295 / 336 | 153.8h |
| 전환 최소 (Setup-aware) | 28.5일 | 62.5h | 240h | 1,295 / 336 | 153.9h |
| 규격 우선 (Spec-based) | 28.5일 | 68.5h | 246h | 1,349 / 282 | 166.0h |
| **최적화 엔진** | **26.2일** | **51.0h** | 250h | 1,240 / 391 | **141.4h** |

**해석** — 최적화로 확관 전환시간은 41% 줄지만 Makespan 개선은 8.2%에 그칩니다.
현재 계획의 전체 병목이 확관이 아니라 **포장 및 출하(가동률 93%)** 이기 때문입니다.
확관 최적화의 실질 효과는 **전환 손실 감소 · 재공(WIP) 감소 · 호기 부하 균형**에서 나타납니다.

## 4. 표준시간 산출식

`src/engine.js` 가 엑셀 「Total Summary」의 19개 공정 산출식을 구현합니다.
`data/tables.json` 은 WPS 용접속도, 1st-UT 절단속도, 확관 다이 Step Size, End-Facing 저속절삭,
수압 충수시간 등 룩업 테이블입니다.

### 단위 해석 (재현 시 반드시 동일하게)

원자료의 "제품 Spec 길이"가 공정마다 단위가 다릅니다. 잘못 잡으면 결과가 수 배 어긋납니다.

| 공정 | 길이 단위 | 비고 |
|---|---|---|
| Press Bender, Gap Press | **m** | 예) `178 + 12.802/0.708 − 914/170 + X1(12회)×36 = 622.7s` |
| Edge Miller, Pre Bender, 용접, UT, 포장 | **mm** | |

그 밖의 해석:

- **확관 횟수 N** = `ceil((L_mm − 500) / step) + 2`, **짝수면 +1 (항상 홀수)**.
  `step` 은 확관 1호기 다이표에서 (인치, 두께)로 조회
- **수압** 2차 압빼기·에어 벤트는 분 단위 (18" = 3분·2분, 36" 이상 = 5분·3분)
- **포장** 의 `250s × floor(지시량/10)` 은 10본마다 추가 검사 → 본별로 `seq % 10 == 0` 일 때 `+250s`
- Expander(2호기) 시트는 원본이 비어 있어 1호기 다이 테이블을 공용으로 사용

### 검증

```bash
node tools/verify_formulas.js     # 20개 산출식을 엑셀 손계산과 교차검증
node tools/verify_ui.js           # 2D·3D 브라우저 렌더링 · 탭 전환 · 필터 · CSV (playwright 필요)
```

`tools/verify_formulas.js` 는 전 항목 PASS 를 확인한 상태입니다.

## 5. 시뮬레이션 모델

- **단위** — 파이프 1본 단위 FIFO 디스패치
- **라우팅** — 길이 > 13m → 18M 라인 / 이하 12M 라인. 두께 25T 초과 → Gap Press.
  단일 오더 API 5L 또는 50PCS 이상 → 1차 U.T, 그 외 By-pass.
  RB 라인 투입 조건(전부 만족): 두께 25T 이하 & 외경 24" 이하 & 병목 발생 시.
  API 5L → Final U.T + 관단 X-ray, 프로세싱 파이프(A671/A672)는 별도 요청 시에만 Final U.T
- **교대** — Shift당 실가동 7.5H 기준. 가동 시간대에만 작업이 진행되고 비가동 시간대는 이월
- **설비 전환** — 직전 처리 제품과 외경/두께/길이가 다를 때 설비별 툴·다이·클램프 교체 시간 부가 (`src/engine.js` 의 `CHANGEOVER`)
- **표준시간** — 가동률을 고려하지 않은 **Net Time** (원자료 NOTE 1번)

## 6. 빌드

산출물(`dist/`)은 커밋되어 있으므로 **그냥 열어서 쓰면 됩니다.** 소스를 고쳤을 때만 빌드하세요.

```bash
# 2D
python3 build.py

# 3D (three.js 를 vendor/ 에 먼저 받아야 함 — 이미 커밋되어 있으면 생략)
python3 tools/fetch_three.py
python3 build3d.py
```

데이터를 원자료에서 다시 만들려면:

```bash
pip install openpyxl
python3 tools/extract_tables.py "★JCOE 공정 생산 표준 시간 분석 - 20251218 (POSTECH 송부).xlsx"
python3 tools/extract_orders.py legacy/JCOE_view2.html
```
